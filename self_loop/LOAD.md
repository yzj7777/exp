# self_loop —— 加载入口（给新会话里的 agent 读）

你被要求加载本工具。你的任务：**对 `self_loop/state/TODO.md` 顶部记录的课题进行无限循环挖掘**，
直到信息饱和（协议判定）或用户叫停。

## 铁律（先读，违反即失败）

1. **课题锁定**：课题是 TODO.md 标题里那段"课题原文"（用户的第一次提示词）。不要换成别的课题，
   不要修改 PROTOCOL.md，除非用户明确要求。
2. **磁盘即记忆**：课题进度、已有发现、已问过的问题，全部只在 `self_loop/state/`。
   你自己的"记忆"和"上一轮的印象"不可信 —— 每轮一律先读盘。
3. **回合内全自动**：一轮结束（落盘后）立即开始下一轮，不问用户。
4. **回合间靠心跳**：接近本回合上下文极限、或每完成 3 轮时，结束本回合并用 `ask_user` 给出
   【继续挖下一轮】【停止并写报告】【换方向】。用户点"继续" = 直接开新一轮（先 tick 恢复状态），
   不要寒暄、不要重新介绍工具。
5. **饱和才停**：只有 TODO 耗尽且无新子问题、或连续 2 轮零新发现，才写 `state/REPORT.md` 收尾。
   上下文撞墙不是停止理由 —— 那是滚入新回合的信号（状态无损）。

## 启动步骤（严格按序）

1. 定位仓库：当前目录有 `self_loop/` 就用它；否则 `find / -maxdepth 5 -name LOAD.md -path '*self_loop*' 2>/dev/null`，再不行问用户仓库路径。
2. `cd` 到仓库根目录（`self_loop/` 的上一级）。
3. 读 `self_loop/PROTOCOL.md` —— 这是每一轮都原样执行的固定提示词。
4. 运行 `bash self_loop/tick.sh` 加载状态视图（迭代号 / 下一个问题 / 最近发现）。
5. 用一句话向用户确认：课题是什么、已完成几轮、下一问是什么 —— 然后**立即开始第 1 轮**，不再等指令。

## 能力降级预案

- 有 `web_search` / `fetch_page`：正常使用（主路径）。
- 没有网络检索工具：用 bash 内可用的检索手段；若确实没有任何检索能力，基于 PROGRESS.md
  已有发现做综合、交叉核对与推演，所有推断必须标注 `(inference, unverified)`，并在 ITERATIONS.md 记录能力受限。
- 没有 `ask_user`：回合结束时用普通消息列出三个选项让用户回复。

## 结束时的交付

写 `self_loop/state/REPORT.md`：课题原文 / 迭代总数 / 完整发现（带来源）/ 未解问题 / 建议的后续方向。
然后告诉用户报告路径，循环结束。
